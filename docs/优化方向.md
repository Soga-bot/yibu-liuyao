# 易卜六爻 · 优化方向（Roadmap）

> 按 P0→P3 排列；每项含现状、目标、做法。完成一项请在 `开发日志.md` 补记录并更新本文状态标记。

## P0 —— 打通产品主链路（不做完不算"能用"）

### 1. 3D 摇卦 → 排盘闭环 ✅ 2026-08-24 已完成（含摇一摇/震动/横竖屏增强）

- **现状**：铜钱落定后只停在场面上，不读正反面、不成爻、不跳转——首页"摇卦起卦"进去是死路。
- **目标**：3D 页内摇 6 次铜钱 → 自动成卦 → 跳转排盘页展示完整盘面。
- **做法**：
  1. **正反面判定**：落定时铜钱 `rotation.x/z` 已 snap 到 π 整数倍——用 `Math.round(rot / π) % 2`
     区分字/背面（需先确认模型默认面朝向，跑一次调试即可标定）；
  2. **成爻映射**（金钱卦标准，背=阳）：3背=老阳`{yin:false,dong:true}`｜0背=老阴`{yin:true,dong:true}`｜
     1背=少阳`{yin:false,dong:false}`｜2背=少阴`{yin:true,dong:false}`；
  3. **6 爻累计**：页面维护 `lines[]`，每摇完一爻入列并画小进度（复用 `placeCoinsIdle` 待机位）；
  4. **带参跳转**：`wx.navigateTo('/pages/paipan/paipan?yao=<6位串>&dong=<位串>&gz=<甲子>')`，
     `paipan` 页 `onLoad(options)` 解析参数直接 `onPaipan()`。
- **验收**：3D 页摇 6 次 → 自动落在排盘页且卦名/世应/动爻正确；中途退出可重摇。

### 2. git 版本管理

- **现状**：无任何版本控制，误删无法回滚（本次整理删了 30+ 文件全靠人工核对）。
- **做法**：`git init` + 首次提交；`.gitignore` 至少含 `.mypy_cache/`、`node_modules/`；此后每完成一个 P 项一次提交。

## P1 —— 高性价比补全（数据已就绪，只欠 UI/体力活）

### 3. 典籍库页 `pages/dianji` 接真数据 ✅ 2026-08-24 已完成（64 卦列表+搜索+详情页 `pages/dianji/detail`；十翼仍归 P2-7）

- **现状**：占位页；而 `GUA_LIST`（64 卦全字段）+ `tools/reference/zhouyi.txt`（彖传/象传/文言/系辞/说卦/序卦/杂卦全文）已在手。
- **做法**：列表页按文王序渲染 `GUA_LIST`（卦名/卦象/宫/大象传）；点入详情页展示卦辞+六爻爻辞+用九用六；
  十翼文本做二级 Tab。长列表用 `scroll-view` + 分页或 `recycle-view`。
- **验收**：64 卦可浏览、可搜索（按卦名/宫），详情信息与 `paipan` 排盘结果一致。

### 4. 3D 体积优化 ✅ 2026-08-24 已解决（结构调平衡）

- **诊断**（推翻早前"压贴图"判断）：模型贴图本就很小（shell 内嵌 webp 56KB、coin PNG 11KB），
  体积大头是 **float32 顶点属性**（shell 878KB/2.4万面、coin 643KB/6.5千面）；
  量化 `KHR_mesh_quantization` 可解但 **r108 引擎不支持**（r121 才加入）；weld/prune/simplify 实测均无收益。
- **已做**：coin.glb 移到主包 `models/`、shell.glb 留分包 → 主包 ~841KB ✓ / package3d ~1585KB ✓，真机预览可过。
  原模型备份 `tools/reference/models-orig/`。
- **长期**：升级 threejs-miniprogram 移植版（或自行移植新版 GLTFLoader）后对两模型量化，coin.glb 再搬回分包（减小冷启动）。

### 5. 摇卦历史记录 ✅ 2026-08-24 已完成（写入点 `paipan.onPaipan`，同卦去重；mine 页列表/回看/长按删除/清空，上限 100，回看带 `from=history` 防重复记录）

- **现状**：排完盘刷新即丢，无任何持久化。
- **做法**：`paipan` 出盘后写入 `wx.setStorageSync('history')`（含时间/问题/6爻/日干支/卦名）；
  `pages/mine` 渲染列表 + 详情回看（重放 `paipan()` 即可复原盘面）+ 删除/清空。上限 100 条。
- **验收**：杀进程重进历史仍在；点历史条目能复原完整盘。

## P2 —— 内容与体验深化

### 6. 白话翻译层

- **现状**：只有古文原文（卦辞/爻辞/大象传）。
- **做法**：`data/gua.js` 加 `guaci_yi`/`ci_yi` 字段，译本需可靠来源（如通行译注本），仍走生成脚本注入，
  **保持"不杜撰"原则**；UI 在原文下方折叠展示"译"。

### 7. 彖传/小象入库 + 解卦参考

- **做法**：扩展 `gen-gua-data.mjs` 解析 `zhouyi.txt` 彖传/象传段（格式与经文不同，按"彖曰/象曰+卦名"重新分段），
  入库后 `paipan` 详情与典籍库共用。

### 8. `pages/paigua` 排卦解卦页 ✅ 2026-08-24 已完成（术语速查卡：六亲/六神/用神选取/空亡世应 + 摇卦/手动排盘快捷入口；tab 同步更名「解卦」）

- **定位**：轻教学 + 查询：六亲含义、六神含义、用神选取规则、空亡/世应速查——引擎已有全部数据，
  主要是内容编写与 UI；与典籍库共用组件。

### 9. 分享与体验细节

- 卦象分享卡片（canvas 绘制：卦名+六爻+一句话）、摇卦音效、`onShareAppMessage`、深色模式适配。

### 10. 首页与交互体验打磨（外部 UI/UX 评审借鉴，2026-08-24 筛选）

> 来源：一份外部 UI/UX 评审建议，与项目现状比对后筛选。评审中已实现/不适用的部分不收录：
> 3D 摇卦闭环、CSS 铜钱质感、按钮按压缩放、分包与体积控制、审核红线规划（见 P3-12）均已就位；
> 按钮圆角回改 16-20px、色号体系大改、排盘/典籍再分包、铜钱图压缩（纯 CSS 无图片）经评估不采纳。

按性价比排序（**建议实施顺序：先 2+3（审核安全），再 1**）：

1. **快捷入口卡片化**：首页「卦辞典籍/五行基础」现为裸文字，可点感知弱 → 改胶囊卡片 + 箭头小图标；
2. **起卦前静心提示**：点「摇卦起卦」先弹「一事一问，静心默念所问之事」确认再进 3D 页——仪式感 + 强化文化演示定位；
3. **免责声明升级**：文案改「本工具仅供传统文化研究参考，不构成人生决策依据」；排盘结果页底部补一行小字（目前仅首页有）；
4. **点铜钱触发摇卦**：首页铜钱区域 `bindtap` 复用 `onShake`，趣味交互；
5. **排盘页点按反馈**：爻线、「静/动」按钮加 `hover-class` 触感；
6. **首次使用引导弹窗**：说明「摇卦 vs 手动排盘」两种模式差异，可与 P1-5 历史记录合并做；
7. **TabBar 图标自查**：线性风格统一、选中态用古金色。
