## 3. 核心引擎 `utils/liuyao.js`

### 3.1 数据约定（全项目统一）

- **6 位 key**：初爻→上爻排列，`1`=阳 `0`=阴。例：乾=`111111`，坎=`010010`。
- **爻对象**：`{ yin: bool, dong: bool }`——`yin` 阴阳，`dong` 动静（动=老阳/老阴）。
- **爻位 pos**：1=初爻 … 6=上爻（数组下标 = pos-1）。

### 3.2 排盘算法（火珠林/京房易标准）

| 模块 | 实现 | 位置 |
| --- | --- | --- |
| 八卦 | `[初,中,上]` 三 bit 表示，查表转卦名 | `BAGUA_LIST` |
| 纳甲 | 内/外卦各配天干+三地支 | `BAGUA_NAJIA` |
| 卦名 | 8×8 矩阵：行=上卦、列=下卦 | `GUA_NAME` |
| 八宫世应 | **京房变卦法程序化生成**（见下） | `buildPalaceTable()` |
| 六亲 | 宫五行为"我"，五行生克推导 | `wuxingRelation` + `REL_TO_LIUQIN` |
| 六神 | 日干起青龙，初→上顺布 | `shenStartByGan` |
| 旬空 | 日干支序号→旬头→旬前二支 | `kongWangByGanZhiIdx` |
| 变卦 | 动爻取反后重查卦名 | `paipan()` 内 |
| 公历→日干支 | JDN 公式，`(jdn+49)%60`（已验证 2000-01-01=戊午） | `dateToGanZhi` |

**八宫世应生成法**（不背 64 卦表，纯推导）：每宫从纯卦（世 6）出发，1~5 逐爻变得一世~五世（世 1~5）；游魂卦在五世基础上第 4 爻回变（世 4）；归魂卦内卦复位为本宫（世 3）。应爻 = `((世+2) % 6) + 1`。

**六神起点**：甲乙→青龙、丙丁→朱雀、戊→勾陈、己→螣蛇、庚辛→白虎、壬癸→玄武。

### 3.3 API

```js
paipan({ yao, dayGan, dayZhi })   // 主函数 → 完整排盘对象（见下方返回结构）
hexagramFromKey(key)              // 6位key → { key, name, gong, nei, wai, shi, ying }
listAllHexagrams()                // 全部 64 卦（八宫构建序）
dateToGanZhi(date)                // Date → { gan, zhi, idx }
kongWangByGanZhiIdx(idx)          // 干支序号 → 两个空亡支
wuxingRelation(a, b)              // 五行关系（比和/我生/生我/我克/克我）
```

`paipan()` 返回：`{ name, gong, gongWuxing, nei, wai, shi, ying, dayGan, dayZhi, kongWang[], lines[6], bian }`；每爻 `lines[i] = { pos, yin, dong, gan, zhi, wuxing, liuqin, liushen, isShi, isYing, kong }`。

### 3.4 测试

```bash
node utils/liuyao.test.mjs
```

覆盖：乾为天全盘逐爻（纳甲/六亲/世应/六神/空亡）、坎为水、地天泰（世 3 应 6）、丁日六神起朱雀、乾二爻动变天火同人。当前 **22/22 通过**。

## 4. 知识库 `data/gua.js`

### 4.1 生成流水线

```bash
node tools/gen-gua-data.mjs   # 重新生成 data/gua.js（勿手改，改脚本再生成）
```

三个数据源合并：

| 来源 | 提供内容 | 匹配方式 |
| --- | --- | --- |
| 引擎 `listAllHexagrams()` | 卦名、卦宫、上下卦（已 22/22 验证） | 按卦 |
| `tools/reference/fuxi-gua.json` | 大象传 daxiang、简短描述 desc | 按卦名 |
| `tools/reference/zhouyi.txt` | 卦辞、384 爻辞、用九/用六（《周易》原文） | 按卦名+爻题 |

爻题（初九/六二…）由规则生成（阳配九阴配六；初/上位置在前），并与原文爻题交叉验证——**对不上即视为缺文**。

### 4.2 硬校验（不过即拒绝生成）

- 卦辞 `64/64`、爻辞 `384/384`、用九用六 `2/2`；
- 经文区出现任何未识别行会打印警告（防折行/格式异常静默丢失）。

### 4.3 周易原文解析规则

- 文件为 UTF-8（由 GB18030 转码而来），只解析 `【上经】`~`【彖传上】` 之间的经文；
- 段落结构：`X卦第N` 标题行 → `卦名：卦辞` → `爻题：爻辞`×6（乾坤多一行用九/用六）；
- **特判：坎卦经文卦名作「习坎」**（古本特征），前缀匹配时剥离"习"字；
- `【下经】` 等分节标记跳过；
- 其后 60% 内容（彖传/象传/文言/系辞/说卦/序卦/杂卦）暂未入库，保留在原文中供典籍库页使用。

### 4.4 字段说明

| 字段 | 含义 |
| --- | --- |
| key / seq / name / gong | 6位key / 文王序 1-64 / 卦名 / 卦宫 |
| nei / wai / neiXiang / waiXiang | 下上卦名及自然象（天地雷风水火山泽） |
| daxiang / desc | 大象传 / 一句话导语 |
| guaci / yaoci[{ti,ci}] | 卦辞原文 / 六爻爻题+爻辞原文（初→上） |
| yong | 仅乾坤：`{ti: 用九/用六, ci: 原文}` |

导出：`GUA_DATA`（按 key 查表）、`GUA_LIST`（按文王序数组）、`getGua(key)`。

## 5. 3D 分包 `package3d`

- **引擎**：threejs-miniprogram 预打包整包。**不含 DRACOLoader**——模型必须是非 Draco glb（当前两个模型已实测 `KHR_draco_mesh_compression` 计数 0）。
- **加载方式**：`FileSystemManager.readFile`（小程序根路径）→ ArrayBuffer → `GLTFLoader.parse()`，不走网络。
- **物理模拟**（`divination.js` 顶部参数可调）：`GRAVITY=24`、`FLOOR_Y=-1.0`、`BOUNCE=0.34`；落定时角度吸附到 π 整数倍（铜钱躺平）。
- **龟壳朝向**：模型原始开口朝下，用 `SHELL_ADJUST.rotX = π` 翻成碗状，位置/缩放补偿同在此对象。
- **闭环（2026-08-24 已通）**：落定读正反面（`(k+m)` 奇偶，`BACK_PARITY` 标定）→ 三钱成爻（背=阳：3背老阳动/0背老阴动/1背少阳/2背少阴）→ 摇满 6 爻 `navigateTo('/pages/paipan/paipan?yao=&dong=')` 自动出盘。
- **真机增强**：摇一摇起卦（加速度计 |Δ|>12 触发，冷却 1.2s）、震动反馈（成爻 light / 卦成 heavy）、横竖屏自适应（`pageOrientation: auto` + `onResize` 更新相机）。工具内模拟不了，需真机预览。详见 `libs/THREE-SETUP.md`。

## 8. 编码与协作约定

- 全部文本文件 UTF-8（无 BOM）；引入外部 txt 注意先验编码（本次 `周易.txt` 即 GB18030）；
- 知识库内容**只改生成脚本、不改产物**；经典原文不杜撰，缺失宁可留空；
