## 二、`772d8a4` 第二刀：撤预载引用（本日关键决策）

- **现象**：改名后报错变为 `packageEngine/ 未找到`（同位置两条，截图存证）。
- **核规**：拉官方文档对照——preloadRule 的 packages **可填 root 或 name（均合法）**；
  纯 JS 分包 + require.async 是「分包异步化」钦定用法。配置本身无误。
- **判定**：工具侧未把 `pages:[]` 空页面分包登记进预载校验表（查的是路径表，空 pages
  分包可能根本不进表）。另有次级嫌疑：`git mv` 移动目录致工具文件树缓存滞留。
- **处置（保运行优先）**：撤掉首页/问事页两条对 packageEngine 的预载引用
  （packageBooks 预载保留），引擎改「进摇卦页现下载」（0.67M，页面本就有
  「3D 引擎装载中…」文案 + failed→redirectTo 重试兜底）。
  **代价仅 wifi 抢跑优化，体积治理成果（各包回 1.5M 线内）分毫不动。**
- **恢复预载的后路**：给 packageEngine 挂极简占位页（pages 非空）再试，或等工具链修复。
- **结果**：编译通过。控制台见 `Launch Time: 1591 ms`、`preloadSubpackages: success`。
