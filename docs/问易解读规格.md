# 问易解读 · 本变合参规格（AI 后端接入契约）

> 立档：2026-08-26（v0.3.0-③）。2026-08-27（v0.3.24）落地三件：本地合成模拟层、
> 云函数脚手架、严格提示词 v1——端上管线全通，云端只差开通与灌 key。
> **密钥不下发小程序端**：真实接入走微信云函数 `cloudfunctions/wenyi`（供应商 key
> 只存云函数环境变量）；端上由 `utils/wenyi-config.js` 的 `WENYI_MODE` 三态切图。

## 一、问题背景

有动爻即有变卦时，此前的解读设想是本卦、变卦**各自**结合所问解读——两篇并读，
主次不明。传统纳甲筮法的读法是**以本卦为现状、动爻为几微、变卦为趋向**，一篇
合参。故定本规格：**单篇综合解读**，不再分卦各说。

## 二、请求契约（端 → 云函数）

`wx.cloud.callFunction({ name: 'wenyi', data: … })`，data 字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| yao | string | 本卦六爻 `01` 串，**初爻→上爻**（1 阳 0 阴），与引擎/GUA_DATA 键同构 |
| dong | string | 动爻 `01` 串，同序；全 0 = 无动爻（无变卦） |
| gz | string | 日干支（如 `甲子`） |
| q | string | 所问之事（≤30 字，可为空） |
| name | string | 本卦名（服务器应按 yao 复核，不以端上为准） |
| bian | string | 变卦键（无动爻为空串） |
| bianName | string | 变卦名（同上） |

响应：`{ "text": "…" }`（纯文本，段落以 `\n\n` 分隔；端上直接渲染并落库）；
失败为 `{ errCode, errMsg }`，端上一律降级本地合成。

云函数端自带《周易》经文库与排盘引擎快照（`cloudfunctions/wenyi/data.js` /
`liuyao.js`，由 `tools/gen-wenyi-cloud.mjs` 从 `data/gua.js`、`utils/liuyao.js`
机械生成并自校验），按 yao/dong/gz **服务端复核**卦名与变卦（端上 name 不符仅记
log，以复核为准——不信任端上富数据，杜绝经 payload 注入提示词）。经文从库内取
**传世本原文**逐字注入 user 消息【经文原文】块，不得让模型凭记忆生成经文
（不杜撰原则同样约束 AI 层）。

## 三、解读结构（四段，有变卦时）

1. **本卦现状**——所问之事在本卦格局下的处境。要素：卦名卦象义、宫与六亲布局、
   世应（自处与所对）、日干支与用神衰旺（服务器按 gz 推）。
2. **动爻之几**——逐条动爻引**该爻爻辞原文**（引号标注，注明爻题，如「九五」），
   说清事态变化的枢机所在。多动爻按位次陈述，以上爻/世爻为重点收束。
3. **变卦趋向**——变卦名与卦象义、变卦宫，事态演变方向的概括；可引变卦卦辞一句。
4. **合参所问**——扣住 q（为空则就卦论卦，不虚构具体所问），三两句收束：现状
   （本卦）→ 关键（动爻）→ 趋向（变卦）。措辞为「事态分析」，**不断言吉凶祸福、
   不给趋避指令**。

无动爻（无变卦）时为三段：本卦现状 / 卦爻辞参读（静卦以卦辞与世应为主）/ 合参所问。

## 四、口径与红线（与全站一致）

- 生成文字属**传统文化参考**，结尾附一句「以上为《周易》文辞的传统解读视角，
  仅供传统文化研究参考，不构成人生决策依据」（端上 wenyi 页已有固定声明，服务端
  可不重复，但正文不得出现相反承诺）；
- 禁用词：算命、预测、占算、改运、运势、消灾、法事；不涉医疗/法律/投资指令性建议；
- 引经必须出自传世本（服务器文本库），拿不准的引文宁可不用；
- 长度建议 400–700 字；四段小标题可用「本卦 / 动爻 / 变卦 / 合参」样式。

## 五、落库与回看（端上已就绪）

解读 text 由端上 `saveAiText` 写入 `ly_history` 对应条目的 `ai { text, at, src }`
（`src`：`'mock'|'cloud'`；历史旧数据无 src 视为云端）；「我的」页出现「问易」
标记，卦成页主按钮分态「回看 · 问易解读」（v0.3.0-②）。
重新生成 = 覆盖同一条目的 `ai`。

## 六、呈现方式（2026-08-26 补记）

- 问易页以**整篇合参解读为主体**（四段单篇，不拆本卦/变卦两篇并读）；
- 本卦、变卦的经文**不在解读内重复**：卦成页已并排本/变卦两框并分列经文讲解
  （卦辞/彖象/白话，点爻行可展开爻辞），典籍库详情可逐卦细读——即
  「整合讲解在先，本卦、变卦各自可读」的结构，现有页面已承载；
- 问易页解读下方可再附「本卦经文 / 变卦经文」折叠段（服务器文本库直出原文），
  版面实施时定，与本规格不冲突。

## 七、模拟层与模式切图（2026-08-27 · v0.3.24）

`utils/wenyi-config.js` 的 `WENYI_MODE` 三态（唯一改动点）：

| 值 | 形态 | 说明 |
| --- | --- | --- |
| `''` | 未开通 | 引导先读本卦/变卦原文（v0.3.24 前旧态） |
| `'mock'` | 本地合成（**当前默认**） | `utils/wenyi-mock.js` 纯函数合成：排盘 + 经文库 + 断法口径规则，零随机零联网；页面标「模拟」，落库 `ai.src='mock'` 回看带「本地合成」标注 |
| `'cloud'` | 云函数 | `wx.cloud.callFunction`；失败自动降级 mock（toast 提示）；落库 `ai.src='cloud'` |

本地合成器同时是云端提示词的**口径基准**：四段结构、用神速选词表、敏感所问
三类提示、400–700 字长度带，两侧保持一致；它也充当云函数故障时的离线降级。
`app.js` 仅在 `WENYI_MODE==='cloud'` 且配了 `WENYI_CLOUD_ENV` 时才 `wx.cloud.init`。

**提示词与禁词字面量只放云端**：七禁词的枚举全站仅两处——
`cloudfunctions/wenyi/prompt.js` 的 `BAN_WORDS` 行与 `utils/wenyi.test.mjs` 的
正则（均被 packOptions 排除出包；`.test.mjs` suffix ignore 系 v0.3.24 修复的
存量隐患）。包内可见文本由 `wenyi.test.mjs` 的包全域扫描守住（当前清零）。

## 八、云函数部署（切 `'cloud'` 前的用户操作）

1. 微信开发者工具开通云开发 → 创建环境 → 环境 ID 填入
   `utils/wenyi-config.js` 的 `WENYI_CLOUD_ENV`；
2. 备供应商三要素——**已定豆包（字节 · 火山引擎火山方舟）**，OpenAI 兼容：
   `WENYI_BASE_URL` = `https://ark.cn-beijing.volces.com/api/v3/chat/completions`；
   `WENYI_MODEL` = 方舟控制台显示的 Model ID（形如 `doubao-seed-1.6`、
   `doubao-1.5-pro-32k` 或 `ep-` 推理接入点）；`WENYI_API_KEY` = 方舟 API Key。
   完整实操与注意项见 [AI问易接入方案.md](AI问易接入方案.md) §七；
3. IDE 中右键 `cloudfunctions/wenyi` →「上传并部署：云端安装依赖」；
   云开发控制台为该函数配置环境变量并确认超时 60s（config.json 已带）：
   - `WENYI_BASE_URL`：完整接口地址（含 `/chat/completions` 路径）
   - `WENYI_API_KEY`：供应商密钥（只存云端，不进代码不进包）
   - `WENYI_MODEL`：模型名
   - `WENYI_TIMEOUT_MS`：HTTP 超时（默认 45000，须小于函数 60s 超时）
4. `utils/wenyi-config.js` 切 `WENYI_MODE='cloud'` → 即 v0.4.0。

msgSecCheck 说明：`config.json` 已声明 `security.msgSecCheck` 权限；输入侧
fail-open（接口不可用仅记 log 放行），输出侧**明确风险**才拒发（接口不可用记
log 放行）——权限未开通时功能可用，日志会有告警，后续在控制台补开即可。

改 `utils/liuyao.js` 或 `data/gua.js` 后：`node tools/gen-wenyi-cloud.mjs`
重新生成云函数快照（自校验不过会 exit 1，阻止坏快照上线）。
